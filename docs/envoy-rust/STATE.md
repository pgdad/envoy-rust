### Phase-24 state-1 brainstorm

- **Phase pick + scope (ADR-0060).** Phase `24` = **`envoy.filters.http.csrf`**, the HTTP-filter-family's SIXTH concrete phase (after 09 local_ratelimit / 10 rbac / 11 fault / 22 jwt_authn / 23 cors) and the **SECOND consumer of the phase-23 per-route `typed_per_filter_config` infrastructure**. The pick is driven by the §6.3 anti-pattern: phase 23 landed the per-route-config infra but registered only the `Cors` variant; a second tested consumer is needed to prove it generalizes additively. `csrf` is the standout: deterministic, header-only, locally-verifiable, reuses existing infra, and — decisively — the cross-cutting HCM route-early-resolution risk that made phase 23 borderline is GONE (phase 23 landed `resolve_route` + the `apply_route_config` threading), so phase 24 is a near-pure additive plug-in (an enum arm + a filter module), the lightest filter phase since the framework completed.
- **Alternatives rejected at the brainstorm:** `buffer` (request-body-buffering machinery — higher risk; deferred to its own phase); per-route overrides of existing `fault`/`rbac`/`local_ratelimit` (lower new-surface value; the interesting route>vhost `mostSpecificPerFilterConfig` cascade was deferred at phase 23); `compression` (gzip foundations-ADR + non-byte-exact body comparison); `ext_authz`/`ext_proc` (external auth service / gRPC still H2-trailers-blocked); load-balancing family (non-deterministic distribution / byte-exact hash-ring reproduction / distinguishable-backend harness). The phase-23 M23-6/M23-7 connection-handling hardening was offered as a fold-in foundation slice and DECLINED — kept as M-track follow-ups to keep phase 24 single-purpose.
- **Minimum-viable scope (SPEC §3):** the second `PerFilterConfig::Csrf(CsrfPolicy)` variant + a near-empty filter-chain `Csrf` entry + a `CsrfPolicy` schema (`additional_origins: Vec<StringMatcher>` reusing 04.x + `filter_enabled` deterministic-0%/100% only per the phase-11 fault precedent); `CsrfFilter` (eighth `HttpFilterInstance` variant; first decode-side-only per-route filter — modify-method origin guard, `Origin`/`Referer` vs `Host` + `additional_origins`, 403 `StopAndSend` on mismatch/missing-source via the existing filter-synth helpers; per-route policy via the existing `apply_route_config` hook — NO HCM change); `http.<stat_prefix>.csrf.{request_valid,request_invalid,missing_source_origin}` stats; fixture `0032-http-filter-csrf` (H1, real upstream cluster per ADR-0058 L6, 5 deterministic probes); in-process backstop; a `parse_bootstrap` fuzz seed (no new target). The existing `PerRouteConfigForAbsentFilter` validator is reused verbatim. _(Superseded in part by the state-2 §6.2 findings — see ADR-0061 / the `### Phase-24 state-2 PLAN-write` subsection: the chain entry is NOT near-empty [required `filter_enabled`]; the origin comparison is scheme-stripped `host[:port]`.)_
- **Deferred (SPEC §4):** `filter_enabled` runtime fractional gating + `shadow_enabled` shadow mode; vhost-level config + the route>vhost cascade; `typed_per_filter_config` for filters OTHER than cors/csrf; streaming/trailers + gRPC-Web CSRF.

### Phase-24 state-2 PLAN-write

- **§6.2 empirical verification (LOCAL Docker, `envoyproxy/envoy:v1.33.0`, digest `sha256:56da5afd…`, 2026-06-11) → ADR-0061.** Full probe transcript in `phases/24-http-filter-csrf/PROGRESS.md` Task-1 preamble. Of the 7 §6.2 items, THREE diverged materially (reconciled by ADR-0061): **L1 (config shape)** — Envoy uses ONE `…csrf.v3.CsrfPolicy` message at BOTH the filter-chain `http_filters[].typed_config` AND the per-route `typed_per_filter_config`, with `filter_enabled` REQUIRED at both (`--mode validate` → `CsrfPolicyValidationError.FilterEnabled: value is required`) — so `HttpFilterTypedConfig::Csrf(CsrfPolicy)` + `PerFilterConfig::Csrf(CsrfPolicy)` (same type, NOT a near-empty `CsrfConfig {}`) + a NEW `RuntimeFractionalPercent { default_value: FractionalPercent, runtime_key: Option<String> }`; **L3 (origin computation)** — source + target origins are reduced to scheme-stripped `host[:port]` (`Url::hostAndPort()`), NOT `scheme://host:port` (verified: `Origin: http://additional.example.com` matches `exact: "additional.example.com"` but NOT `exact: "http://additional.example.com:80"`); source = `Origin`, fallback `Referer` (Origin precedence confirmed); **L6 (chain-base/route-replace)** — the chain-level `CsrfPolicy` is an always-applied base (a route without an override is STILL guarded by it), a per-route `CsrfPolicy` REPLACES it wholesale; `filter_enabled` honored at deterministic 0%/100% (envoy-rust rejects non-deterministic `default_value` + a present `runtime_key` startup-fatal per ADR-0049). CONFIRMED: **L2** modify set `{POST,PUT,DELETE,PATCH}` (safe `{GET,HEAD,OPTIONS,TRACE}` pass, no stat); **L4** 403 `Invalid origin` (14 bytes, no newline, `content-type: text/plain`, `content-length: 14`, `server: envoy` — the H1 `decorate_filter_synth_response` auto-adds `content-type` for non-empty bodies, the rbac precedent); **L5** `http.<prefix>.csrf.{request_valid,request_invalid,missing_source_origin}` HCM-prefixed + MUTUALLY EXCLUSIVE (missing-source does NOT also tick request_invalid); **L7** the generic `PerRouteConfigForAbsentFilter` validator covers csrf verbatim (ADR-0058 L7 stricter-reject); **L8** fixture 0032 needs a real upstream (ADR-0058 L6).
