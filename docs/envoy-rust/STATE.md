- **envoy-rust matches by peeking, not by exposing payload.** `ChainHandler::handle` awaits `TcpStream::peek(&mut [0u8;1])` before invoking any filter; `peek` does not consume, so the terminal handler still receives the whole stream. `Ok(0)` (client closed/half-closed without sending) skips the chain and closes via `close_with_drain`. **The `NetworkFilter` trait shape is UNCHANGED**; filters see only `ConnectionInfo`. **CF-67-3 (payload-visible `on_data`-time iteration + buffering) remains correctly deferred and its scope is unchanged.**
- **A mutation check can report a FALSE PASS from a stale binary.** The ADR-0124 drain mutation initially passed — which would have meant `post_eof_client_write_is_accepted_not_reset` was vacuous. Root-caused with `superpowers:systematic-debugging`: cargo had skipped the rebuild. **Always grep the run for `Compiling <the crate you MUTATED>`** — twice I watched `envoy-bin` while the mutation lived in `envoy-listener`. A standalone TCP probe independently established that no-drain ⇒ `EPIPE`, even at 0 unread bytes.
- **`cx_active` cannot witness reaping**, so the M66-3 witness reads `join_set.len()` via `Listener::pending_tasks_watch()`. Deleting `accept_loop`'s `join_next()` select arm makes it fail with `JoinSet leaked 50 completed tasks`.
- **`expected_stats` on `Driver::TcpWithStats` are post-probe DELTAS.** `run_fixture` opens a readiness `TcpStream::connect` to each proxy's data port before the probe. The witness property survives: `scrape_admin_stat` returns `Ok(0)` for an unregistered name, so an unimplemented filter snapshots 0 and finishes at 0 — a delta of 0, which fails any non-zero expectation.
- **Two pre-existing artifacts had to move, neither weakened.** `rejects_unknown_filter_name` used `envoy.filters.network.rbac` as its example of an *unknown* filter name; it now uses `sni_cluster`, placed **before** a terminal `echo` (every unknown name is non-terminal, so a trailing one would trip the new chain-termination rule first). And `validate_config` in the new backstops captures **stdout and stderr** — envoy-bin's tracing subscriber writes the `ConfigError` line to **stdout**.
- **Exhaustiveness is compiler-enforced, and it was verified.** Adding a `Permission::DestinationPort(_)` arm breaks the build with `error[E0004]: non-exhaustive patterns` at `validate_l4_permission` and the shared tree validator. **Never add a `_ =>` catch-all** — that break is what forces `67.2` to classify every new arm. `clippy::only_used_in_recursion` is allowed on `permission_matches`/`principal_matches` with a note: `conn` is unread by `67.1`'s arms and read by `67.2`'s.
