### Phase-67.1 state-2 PLAN-write — the §6.1 split (active phase)

- **The §6.1 split FIRED, and the re-derived estimate is why.** `SPEC.md` §8 projected ~1740 net LoC; the live-tree re-derivation returned **~2130** against a ~1500 threshold. The SPEC explicitly forbade inheriting its own number — re-deriving found what it had missed.
- **The finding the SPEC missed: a THIRD exhaustive match site.** `define_rbac_tree_validator!` (`crates/envoy-config/src/bootstrap.rs:4087-4148`) is a **single macro instantiated for BOTH `Permission` and `Principal`**. Its shared body matches `Any`/`Header`/`Metadata`/`UrlPath` plus macro-parameterized `$and | $or` / `$not`, exhaustively. The five new L4 arms are **asymmetric** — 3 `Principal`-only, 2 `Permission`-only — so the shared body **cannot name them uniformly**. It needs a variadic extra-leaf parameter, or the two validators must be de-macro'd. `lower_permission` / `lower_principal` (`crates/envoy-filter/src/rbac.rs:262-314`) are the other two sites; **neither carries a `_ =>` catch-all**, so adding arms is a hard compile break — which is the *good* failure mode, and `67.2`'s **X-4** guards against a sibling phase silently adding a catch-all.
- **CF-67-4 MOVED from `67.2` into `67.1`, and this is a correctness decision, not a preference.** `67.1` reuses the existing enums, whose arms include `header`. Upstream Envoy **rejects** `header` matchers in a network `rbac` config (`Found header(name: ":path"…`, measured). Without an L4 leaf allow-list in `67.1`, envoy-rust would accept a config upstream rejects — a **config-load divergence sitting in `main`** for the whole interval between the sub-phases. D-3.3 makes the measured upstream behavior the contract.
- **`67.2` ships no new differential fixture, and that is forced.** The IP arms see the Docker bridge address (`192.168.65.2` on this host) and `destination_port` must match a `{{PORT}}` that **differs between the two proxies** by construction. Not host-deterministic under the harness. Witnessed in-process at `127.0.0.1` with a known port; differential surface is regression-only. Same posture as the phase-`25.1` foundation slice — **recorded in the SPEC and BEHAVIOR_CONTRACT, never silent.**
- **A three-way split was considered and rejected.** The candidate cut — hoisting the accept loop + M66-3 into its own foundation slice — has **no independent observable**: it exists to host the chain pre-hook, and a slice with neither a fixture nor a filter to exercise it is precisely the §6.3 anti-pattern. `67.1` at ~1455 LoC sits under the gate, and §6.1's **mid-execution** valve stays available.
- **`67.1`'s ~1455 LoC is CLOSE to the ~1500 gate.** Its state-2 PLAN-write must re-derive once more, and must remember the mid-execution split valve fires if any single task's sub-steps blow past ~10 items.
- **Both sub-phase directories exist while `67.2`'s row reads `planned`.** §6.2 steps 2-3 mandate creating both directories and both `SPEC.md` files at the split; §6.2 governs over invariant 4.1.3 for splits. The same shape phase `25` took. **Expected state — do NOT invoke `superpowers:systematic-debugging` on it** (§1 Step E).
- **`67.1` is `planned`, not `in-progress`, and that differs from ADR-0064's phase-25 split.** That session *also* landed `25.1`'s `PLAN.md` in the same commit, so STATE pointed at an actively-executing sub-phase. Here §6.2 step 7 mandates an **exit before the PLAN-write**, so `67.1` flips `in-progress` at its own state-2 PLAN-write commit — consistent with invariant 4.1.2's *"only when"* being a **necessary, not sufficient**, condition.
- **Do NOT add `rbac` to `is_terminal_network_filter`** (`bootstrap.rs:825`) — its **absence** is its non-terminality, and the predicate's doc comment names `rbac` as the intended drop-in. **Do NOT add an `on_data` hook** (§6.3; deferred as CF-67-3). **Do NOT materialise a default `Rules`** when `rules` is omitted — the filter is INERT and ticks **neither** counter. **Do NOT let the DENY fixture assert bodies only** — empty-vs-empty passes vacuously; the `rbac.denied == 1` stats assertion is what makes `0072` a witness.
