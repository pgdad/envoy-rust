### Phase-66 state-3 implementation (active phase)

- **The drain is the phase's one real subtlety, and it is now PINNED (ADR-0124).** `direct_response_once` does `write_all` → `flush` → `shutdown()` [FIN] → **read-and-discard until EOF** → drop. The mandatory PLAN Task-4 Step-5 mutation check was performed: commenting out the drain loop makes `post_eof_client_write_is_accepted_not_reset` fail with `Os {code: 32, kind: BrokenPipe}`. Fixture `0071` CANNOT catch this (its driver never writes after EOF) — the in-process test is the only guard. **Do not remove it; do not re-litigate the drain.**
- **`envoy_config::DirectResponse` already existed** — it is the HCM **route-level** `direct_response` action (phase 04). The phase-66 network-filter type is deliberately `DirectResponseConfig`; `TypedConfig::DirectResponse` is an enum *variant* in a different namespace. `BEHAVIOR_CONTRACT.md`'s new `## Network filters` section opens with a do-not-conflate banner because every other `direct_response` row in that document refers to the route-level action.
- **Terminal validation is an immutable PRE-PASS**, placed before the existing `for filter in &mut chain.filters` loop (which borrows mutably — the HCM arm calls `as_mut()`). That ordering also reproduces upstream Envoy's error precedence: a chain of `[direct_response, echo]` reports the TERMINAL error even when the trailing filter is itself malformed. R-0.8 safety was re-confirmed EMPIRICALLY (envoy-admin, envoy-cluster, tls_sni, xds_file_based_lds, xds_file_based_rds all green).
- **`cargo build -p envoy-bin` before ANY local differential run** (memory `differential-harness-uses-debug-envoy-bin`) — the harness executes `target/debug/envoy-bin`, and this phase adds a NEW config key AND a NEW filter name, so a stale binary REDs with `unsupported network filter` / `unknown field`.
- **§7.5 gate (d) is satisfied by the pre-existing `parse_bootstrap` fuzz target** — `direct_response` parses nothing. No new target; the corpus seed needed an explicit `!`-un-ignore line and was proven tracked with `git ls-files`. The state-4 session must RECORD gate (d) explicitly rather than skip it silently.
- **Do NOT "fix" the `echo` `typed_config` asymmetry** (upstream requires it; envoy-rust forbids it — the pre-existing ADR-0014 YAML shim behind fixture `0001`'s two-sided divergence). `direct_response` needs no shim: both sides of fixture `0071` are identical.
