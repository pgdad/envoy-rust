### Phase-25 state-1 brainstorm

- **Pick:** phase `25` = `envoy.filters.http.buffer`, selected at this brainstorm from `MISSION.md`'s §9 HTTP-filters family (the richest remaining vein). The easy header-only HTTP-filter vein is EXHAUSTED — all 7 shipped filters (header_mutation/local_ratelimit/rbac/fault/jwt/cors/csrf) are header-only decode-side decisions and the framework is headers-only (no streaming `decode_data` hook). Buffer is the lightest remaining body-dependent filter (no external service / engine / gzip dep / timing — a pure function of method + body length + policy → deterministic, locally-verifiable, byte-exact differential) AND the THIRD per-route `typed_per_filter_config` consumer (after cors+csrf). Rejected: the LB family (larger/riskier first cut + a new distinguishable-backend harness), the network-filters opener (low leverage), the heavier HTTP filters (external service / engine / non-deterministic), an H2-only buffer (near-cosmetic — exploits H2's incidental pre-buffering, builds no infra), and a pure H1-forwarding phase with buffer deferred (ships a foundation with no consumer). See ADR-0062.

- **Critical recon finding (SPEC §0):** H1 does NOT forward request bodies upstream today — the router forwards an always-empty body (`crates/envoy-http1/src/hcm.rs:356`) and drains+discards the downstream Content-Length body (`:678-697`), a pre-existing gap since phase 04.3; whereas H2 already fully buffers+forwards (`crates/envoy-http2/src/hcm.rs:437-448`). So buffer is NOT a pure plug-in: Part A (now `25.1`) closes the H1 forwarding gap (a regression-equivalence foundation slice), Part B (now `25.2`) adds the filter. The §6.1 split FIRED at the state-2 PLAN-write (ADR-0064).
