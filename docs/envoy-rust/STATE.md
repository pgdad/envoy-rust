### Phase-35 state-1 brainstorm

- **Pick (ADR-0085):** phase `35-rbac-dynamic-metadata` — the FIRST dynamic-metadata CONSUMER. Extend the EXISTING phase-10 `envoy.filters.http.rbac` filter (NO new `HttpFilterInstance` variant) with a string-only `metadata` Permission/Principal condition that reads the phase-33 dynamic-metadata store (written mid-chain by phase-34 `header_to_metadata`). Closes the produce→consume loop the phase-33/34 arc teed up; opens the metadata-consumer vein in the HTTP-filters family.
- **Pivotal feasibility fact (verified at the brainstorm by reading `pipeline.rs` + `rbac.rs`):** the decode pipeline iterates `self.filters.iter_mut()` passing ONE `&mut FilterRequest` to every filter in chain order (`crates/envoy-filter/src/pipeline.rs:77`), so a filter placed AFTER `header_to_metadata` reads the `req.dynamic_metadata` it wrote in the same pass. The fixture chain order `[header_to_metadata, rbac, router]` (producer before consumer) is REQUIRED. `eval_permission`/`eval_principal(p, &FilterRequest)` already receive the metadata-carrying request.
- **Implementation surface (projected):** config — a `Metadata(MetadataMatcher)` variant on the `Permission` + `Principal` enums (the hand-rolled "exactly one map key" `Deserialize` visitors, `crates/envoy-config/src/bootstrap.rs`) + a `MetadataMatcher`/`MetadataPathSegment`/`ValueMatcher` struct trio (single-segment path, `string_match`-only, reusing the 04.x `StringMatcher`, `deny_unknown_fields`); runtime — `RuntimePermission::Metadata`/`RuntimePrincipal::Metadata` + eval arms reading `req.dynamic_metadata.get(filter)?.get(path[0].key)` + the existing `lower_*` arms (`crates/envoy-filter/src/rbac.rs`); the RBAC decision matrix + `403`+`RBAC: access denied` local reply UNCHANGED. Fixture `0043` + an in-process backstop + a `parse_bootstrap` seed + a BEHAVIOR_CONTRACT extension.
- **Scope (ADR-0085 minimum-viable):** single-segment path + `string_match`-only `ValueMatcher`. DEFERS: non-string `ValueMatcher` variants (null/double/bool/present/list/or_match — `present_match` the cheapest follow-up); multi-segment/nested path; `MetadataMatcher.invert`; the other RBAC condition types (IP/port/url_path/SNI); `shadow_rules`; per-route `typed_per_filter_config`; other producers/consumers (jwt_authn `payload_in_metadata`, ext_authz/ext_proc [gRPC-blocked]); `json_format`/gRPC-ALS/OTLP/tracing/stats-sink/tap.
