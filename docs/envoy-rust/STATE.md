### Phase-30 state-1 brainstorm (pick + scope; the subset-LB / maximal-reuse rationale)

> Authored at the phase-30 state-1 brainstorm (`superpowers:brainstorming`). Records WHY phase 30 is `subset LB` + the alternatives weighed; the full reasoning is **ADR-0073**. (Relocates to `STATE_HISTORY.md` per ADR-0035 / §4.1 inv. 9 at the phase-30 state-6 close-out, when row `30` flips `done`.)

- **The pick continues the Load-balancing family with `subset LB`** — the next DETERMINISTIC, byte-exact-differentiable, LOCALLY-observable LB step after the two consistent-hash policies (RING_HASH 28 + MAGLEV 29). Among the remaining LB family, subset LB is the ONLY policy that needs neither a contract-relaxation ADR nor active-HC health state to be differentially exercised: a route `metadata_match` selects a FIXED metadata-matched endpoint subset (deterministic). `least_request`/`random` are non-deterministic (P2C-random / random host → need a contract-relaxation ADR); `priority`/`panic-thresholds`/`locality-weighted` LB cannot be EXERCISED differentially without active-HC/outlier health state or weighted-random — all deferred.
- **subset LB is NOT a `LbPolicy` value** — it is an ORTHOGONAL layer: BEFORE the cluster's existing `lb_policy` picks, it narrows the candidate endpoints to those whose `envoy.lb` metadata is a SUPERSET of the matched route's `metadata_match`, then runs the inner `lb_policy` (MVP ROUND_ROBIN) within the subset. A cluster with no `lb_subset_config` ignores the narrowing → the no-op regression proof (all 37 existing fixtures stay green, round-robin AND RING_HASH/MAGLEV paths).
- **Maximal reuse:** the two-distinguishable-backend `--body-marker` fixture harness (fixtures 0036/0037 + `discover_host_lan_ip`/`{{BACKEND_IP}}`), the `*LbConfig` config pattern, the `pick()`/`pick_endpoint()` threading template (phase-28's `Option<u64>` hash key → the route `metadata_match`), and the no-host 503 path (for NO_FALLBACK) ALL already exist. New surface = endpoint `metadata` + `lb_subset_config` + route `metadata_match` + the `subset.rs` engine + the 3 fallback dispositions.
- **Rejected (ADR-0073):** least_request/random (non-deterministic — a contract-relaxation phase); priority/panic-thresholds/locality-weighted LB (need HC/outlier — post-upstream-robustness); the deferred xDS CDS/LDS hot-reload arc (heavy, split-prone, CI-only differential); other §9 families (network-filters low-leverage; heavier HTTP filters needing external services; gRPC still ADR-0014/H2-trailers-blocked).
- **MVP scope (ADR-0073 / SPEC §2):** endpoint `metadata` (envoy.lb) + `lb_subset_config` (subset_selectors[keys], fallback_policy [NO_FALLBACK/ANY_ENDPOINT/DEFAULT_SUBSET], default_subset) + route `metadata_match` + `subset.rs` (subset index + superset-match) + the `metadata_match`→`pick()` threading + the 3 fallback dispositions + fixture 0038 (two metadata'd backends [stage: prod/canary] + metadata_match routes + a fallback probe) + backstop + a `parse_bootstrap` fuzz seed + a BEHAVIOR_CONTRACT subset row. **Deferred non-goals:** least_request/random; priority/panic/locality-weighted; subset+consistent-hash-inner-LB; multiple overlapping selectors / per-selector fallback / single_host_per_subset / list_as_any / metadata_fallback_policy / scale_locality_weight; subset+EDS-hot-reload; subset+HC/OD differential; CDS/LDS hot-reload.
- **The core differential risk** (envoy-rust must replicate Envoy's EXACT subset selection + fallback to select the SAME backend) is de-risked by the **state-2 §6.2 LOCAL reconnaissance** (record metadata_match→backend mappings + the fallback dispositions + the wire shape against `envoyproxy/envoy:v1.33.0`). **ADR-0074 reserved** (§6.2 reconciliation), **ADR-0075 reserved** (§6.1 split — projected NOT to fire but the closest call since phase 22; ~1100–1500 LoC / ~12–15 tasks; seam 30.1 config+engine / 30.2 pick-threading+fallback+fixture+close). The SPEC was spec-reviewed → APPROVED (0C/1I/4 Minor; ALL folded — the I-1 single_host_per_subset terminology collision + 3 Minors).
