### Phase-31 state-1 brainstorm (pick + scope; the cdn_loop / cleanest-self-contained-differential rationale)

> Authored at the phase-31 state-1 brainstorm (`superpowers:brainstorming`). Records WHY phase 31 is `cdn_loop` + the alternatives weighed; the full reasoning is **ADR-0076**. (Relocates to `STATE_HISTORY.md` per ADR-0035 / §4.1 inv. 9 at the phase-31 state-6 close-out, when row `31` flips `done`.)

- **The pick continues the HTTP-filters family with `cdn_loop`** — the next DETERMINISTIC, byte-exact-differentiable, LOCALLY-observable, maximal-reuse filter. The Load-balancing family's three deterministic policies (RING_HASH 28 + MAGLEV 29 + subset 30) are done; its remaining policies need a contract-relaxation ADR (`least_request`/`random`) or active-HC health state (`priority`/`panic`/`locality-weighted`). The HTTP-filters family is the project's most-developed surface (the H1/H2 pipeline, the 23.x per-route `typed_per_filter_config`, the `StopAndSend` synth helpers, 8 shipped filters), so a new deterministic filter is the lowest-risk maximal-reuse step.
- **cdn_loop is the cleanest fully-SELF-CONTAINED byte-exact differential** among the remaining deterministic filters — a decode-side, header-only RFC 8586 `CDN-Loop` filter: parse the inbound header → count this CDN's `cdn_id` → reject a loop (`count > max_allowed_occurrences`, default 0; projected 502) / reject a malformed header (projected 400) / else append `cdn_id` and forward. Every output (the appended `cdn_id`, the reject body) is static config or a fixed string → cross-proxy byte-identical, with NONE of the per-side host-address dependence that weakened the 28/29 endpoint-strings or the rejected `stateful_session` cookie. LOCALLY observable (no reload trigger).
- **Maximal reuse:** the entire H1/H2 filter pipeline + the decode-side `Decision::StopAndSend` + the H1/phase-11-H2 filter-synth local-reply decorators + the request-header-append path (`header_mutation`) + the `@type`-tagged HTTP-filter config enum + the deterministic HTTP-filter fixture harness (0031/0032/0033 + the echo `--body-marker` backend) ALL already exist. New surface = `CdnLoopConfig` + the RFC 8586 `CDN-Loop` parser + the `CdnLoopFilter` variant + fixture 0039. NO new pipeline machinery.
- **Rejected (ADR-0076):** `header_to_metadata` (internal dynamic-metadata output → needs a cross-cutting `%DYNAMIC_METADATA%` access-log operator [the existing `envoy-accesslog` formatter has none] to be observable — a deferred coupling); `set_metadata` (same, worse — no header input); `stateful_session` (cookie encodes the per-side host address → non-byte-exact); `compressor`/`decompressor` (byte-identical-gzip risk); the remaining LB policies (non-deterministic / HC-dependent); the Observability access-log-operators phase (a viable higher-value family-opener, but moderate differential risk from excluding timing operators — a STRONG future pick, deferred); the network-filters opener (low-leverage); `grpc_*`/`ext_authz`/`ext_proc`/`lua`/`wasm`/`oauth2` (gRPC-blocked or external).
- **MVP scope (ADR-0076 / SPEC §2):** `CdnLoopConfig { cdn_id, max_allowed_occurrences = 0 }` + the `@type`-tagged enum variant + a `cdn_id` validator + the RFC 8586 `CDN-Loop` parser (the correctness gate) + the `CdnLoopFilter` decode-side count/append/reject + fixture `0039-http-filter-cdn-loop` (4 probes: no-header→append / self-`cdn_id`→loop-reject / foreign-id→append-after / malformed→parse-reject) + an in-process backstop + a `parse_bootstrap` fuzz seed (+ a dedicated parser fuzz target if §3 decides) + a BEHAVIOR_CONTRACT cdn_loop subsection. **Deferred non-goals:** per-route `typed_per_filter_config` for cdn_loop (additive later); RFC 8586 `cdn-info` parameter semantics beyond counting; other deterministic filters (header_to_metadata/set_metadata/stateful_session/compressor); gRPC/external filters. Load-bearing invariant: all 38 existing fixtures `0001`–`0038` stay green (the filter is INERT when not in the chain).
- **The core differential risk** (envoy-rust must replicate Envoy's EXACT reject status/body + `CDN-Loop` append formatting) is de-risked by the **state-2 §6.2 LOCAL reconnaissance** (record the four probe outcomes + the parser strictness + the config-validity disposition against `envoyproxy/envoy:v1.33.0`). **ADR-0077 reserved** (§6.2 reconciliation), **ADR-0078 reserved** (§6.1 split — projected NOT to fire; ~600–900 LoC / ~6–8 tasks, comparable to csrf/buffer). The SPEC was spec-reviewed → APPROVED (0 issues; the loop→502 / malformed→400 projections independently confirmed vs Envoy + RFC 8586; 2 advisory notes → the PLAN includes a near-malformed probe).
