### Phase-23 state-1 brainstorm

The next-NEW-PHASE brainstorm (`superpowers:brainstorming`) at HEAD `bd3cfd644` (phase-22 state-6 close-out; ROADMAP rows `00`–`22` all `done`). Picked + scoped phase `23` on the merits across all §9 feature-families.

**Family pick — HTTP filters (the richest remaining §9 vein, ≈13 filters undone).** After 09 `local_ratelimit` / 10 `rbac` / 11 `fault` / 22 `jwt_authn`, the HTTP-filters family remains the deepest open vein. The decisive consideration: the per-route `typed_per_filter_config` infrastructure — deferred at phase 22 (ADR-0055 named `cors` "the natural close site") — is the single highest-leverage unlock in the family, gating `cors` AND `csrf` AND `buffer` AND per-route overrides of all four existing filters. Building it now (with `cors` as the testable first consumer) is strictly higher ROI than extending one filter.

**Filter pick — `cors`.** Fully differential-testable with zero timing/crypto sensitivity (CORS is a pure function of request method + `Origin` + the policy — header-only, no body modification, no clock), and the canonical first consumer of the per-route-config infra. The §6.3 anti-pattern forbids landing the infra without a tested consumer; `cors` is exactly that consumer.

**Three §0 reconnaissance findings (a read-only `Explore` subagent + controller cross-check at HEAD):** (1) **CORS is genuinely per-route in modern Envoy** — the filter-chain `Cors` entry is near-empty; the `CorsPolicy` is attached per-route via `typed_per_filter_config`, which does NOT exist in envoy-config (`Route` `bootstrap.rs:1152-1158`, `VirtualHost` `:1141-1149`, `RouteConfiguration` `:1124-1137` carry zero per-filter config; grep-empty workspace-wide). (2) **The HCM runs the filter pipeline BEFORE it resolves the matched route** (H1 `pipeline.decode_headers` at `crates/envoy-http1/src/hcm.rs:612` vs `build_response` route matching at `:1180-1202`; H2 at `crates/envoy-http2/src/hcm.rs:465-486`) — so a per-route-config filter cannot see its route at decode time today; phase 23 must resolve the route up-front and thread it + its per-filter config into the pipeline. (3) **That route-early-resolution change is regression-safe** — no existing filter reads the route (Router terminus decode no-op `crates/envoy-filter/src/router.rs:28-34`; `build_response` reuses the resolved route for identical dispatch), so all 30 existing fixtures stay green (the 05.1/07.1/12.1/14.1 foundation-slice property). This is the cross-cutting lift ADR-0055 warned about when deferring cors — real, but bounded and regression-safe.

**Alternatives rejected (full analysis in ADR-0057):** the jwt_authn requirement-combinators follow-on (lower leverage — extends one filter); `compression` (gzip foundations-grant + non-byte-exact zlib bodies); the load-balancing family (distribution/hash-exact testing + the missing distinguishable-backend harness); xDS file-watching (deferred a SIXTH time on the three stacked ADR-0050 risks — mutability refactor + timing + Linux-CI-only §6.2); the network-filters family (large stateful protocol parsers, or trivial low-value filters); file-based SDS (low value); the still-blocked gRPC family (H2 trailers).

**Scope locked by ADR-0057 (minimum-viable; SPEC §3/§4).** Delivers: D1 the per-route `typed_per_filter_config` schema (`Route` field + `@type`-tagged `PerFilterConfig` enum [only `Cors` registered] + `CorsPolicy` reusing 04.x `StringMatcher`); D2 the HCM route-early-resolution + threading (H1 + H2, inert for non-CORS filters); D4 `CorsFilter` (decode preflight short-circuit + encode actual-request decoration — the first encode-active feature filter); D7 conditional `cors.{origin_valid,origin_invalid}` stats; fixture `0031-http-filter-cors` (H1; 4 deterministic probes); a new `parse_bootstrap` fuzz seed (no new fuzz target); an in-process backstop; BEHAVIOR_CONTRACT cors rows. Defers: `filter_enabled`/`shadow_enabled` runtime gating, `allow_private_network_access`, vhost-level config + the route>vhost cascade, `typed_per_filter_config` for filters other than cors, the deprecated inline `route.cors` field, gRPC-Web `bypass_cors_preflight`.

**§6.1 split-gate.** Projected single-phase (~1100–1500 LoC / ~10–13 tasks — at the upper edge of the ~1500-LoC gate, the D2 cross-cutting HCM change [H1 + H2] the swing factor). The split valve is held in clear reserve as **23.1** (the per-route-config schema + the HCM route-early-resolution + threading — a foundation slice with no new fixture, proven via regression-equivalence on all 30 existing fixtures, regression-safe per finding 3) / **23.2** (the `CorsFilter` + the `HttpFilterInstance` variant + stats + fixture 0031 + backstop + parent-23 close).
