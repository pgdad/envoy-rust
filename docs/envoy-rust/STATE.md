### Phase-27 state-1 brainstorm (pick + scope; the EDS-hot-reload continuation rationale)

> Authored at the phase-27 state-1 brainstorm (`superpowers:brainstorming`). Records WHY phase 27 is EDS hot-reload + the alternatives weighed; the full reasoning is **ADR-0067**. (Relocates to `STATE_HISTORY.md` per ADR-0035 / §4.1 inv. 9 at the phase-27 state-6 close-out, when row `27` flips `done`.)

- **The pick is a CONTINUATION, not a cross-family fork.** ADR-0065 (phase-26 scoping) explicitly named CDS/LDS/EDS hot-reload "the cleanly-deferred next layers that build on THIS phase's watcher primitive + atomic-swap pattern," and STATE recorded the xDS / dynamic-config family as "the natural continuation now that phase 26 built the watcher + atomic-swap primitive." The remaining fork was *which* of CDS/LDS/EDS goes first.
- **EDS chosen — the LEAST invasive of the three.** An EDS reload mutates ONLY a cluster's endpoint `Vec<SocketAddr>` (`crates/envoy-cluster/src/cluster.rs:80`, read every request by the round-robin LB `pick()` `:274` — per-request stateless, the closest analog to phase-26's stateless route-table swap); the cluster lifecycle (pools/health/outlier/budgets/listeners) stays immutable. It reuses phase-26's entire infrastructure (watcher + atomic-swap + warm-reject pipeline + mid-test-atomic-rename harness) + the phase-21 EDS load path (parser + validator + `cluster.<name>.update_*` stats + `EndpointsConfigDump`). Rejected: **CDS first** (heavier — cluster add/remove spawns/tears-down pools + health checkers + outlier sweepers + budgets + needs a swappable `ClusterManager`); **LDS first** (heaviest — socket bind/unbind + connection drain); **the LB-family opener** (still deferred — needs a GENERAL distinguishable-backend harness; phase 27 builds only its minimal two-single-endpoint-backend seed); **the gRPC/ADS transport** (still ADR-0014/H2-trailers-blocked); **the network-filters opener** (low leverage).
- **Two deliberate scoping calls (correcting an over-optimistic recon):** (1) **MVP = PLAIN clusters only (no active HC / no outlier detection)** — the endpoint-index-aligned `endpoint_health`/`outlier_detection` arrays + the per-`(cluster,endpoint)` health-probe tasks would need spawn/drain/rebuild on a count-changing reload (the same per-endpoint lifecycle churn that defers CDS), so that defers; an EDS+HC/OD cluster's disposition (reject-loud vs no-watcher) is a §6.2/PLAN-write call (ADR-0068 reserved). (2) **A SECOND distinguishable backend is needed** — an endpoint swap WITHIN one cluster is invisible through a single echo backend (`cluster.<name>.membership_total` not emitted `cluster.rs:963`, `membership_healthy` HC-gated, no per-endpoint request counters), unlike RDS's per-cluster `upstream_rq_total` discriminator; the §6.2 may instead select a simpler liveness-flip (200↔503).
- **Carry-forward debt this phase touches** (the M26 block above + prior-phase debt): the watcher-generalization (`RdsWatcher` + the new EDS watcher -> a parameterized `XdsFileWatcher`, the M19-1/M20/M21 + now-two-watchers factoring), M26-1 (read-once-per-request, now applied to the endpoint handle / LB selection), M26-3 (mtime-granularity, inherited by the reused watcher), M26-6 (the now-third atomic-rename test-helper user — the deferred shared-test-support-crate extraction). Folded opportunistically per the "improve code you're working in" discipline; SPEC §6.11.
