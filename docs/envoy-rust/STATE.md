This was measured, not reasoned: Envoy accepts a post-EOF client write at 0 / 21 / 200 000 unread bytes; the naive path raises `BrokenPipeError` **even at ZERO unread bytes**. Fixture `0071` CANNOT catch this (its driver never writes after EOF) — which is exactly why PLAN Task 4 Step 5 is a mandatory mutation check.
- **Two entry-point facts that a plausible-looking plan got wrong.** `crate::parse_bootstrap` **parses AND validates** (`crates/envoy-config/src/lib.rs:769-782`) — there is no `load_bootstrap_from_str`; and `crates/envoy-config/src/error.rs` does **not** exist (`ConfigError` lives at `lib.rs:60`). Task-1's schema tests consequently use `serde_yaml::from_str::<Bootstrap>` (7 existing call sites establish the convention); Tasks 2-3 use `parse_bootstrap`.
- **Terminal validation is an immutable PRE-PASS**, placed before the existing `for filter in &mut chain.filters` loop (which borrows mutably — the HCM arm calls `as_mut()`). That ordering also reproduces upstream Envoy's error precedence: a chain of `[direct_response, echo]` reports the TERMINAL error even when the trailing filter is itself malformed.
- **Do NOT "fix" the `echo` `typed_config` asymmetry** (upstream requires it; envoy-rust forbids it — the pre-existing ADR-0014 YAML shim behind fixture `0001`'s two-sided divergence). `direct_response` needs no shim: both sides of fixture `0071` are identical.
- **§7.4 gate (d) is satisfied by the pre-existing `parse_bootstrap` fuzz target** — `direct_response` parses nothing. No new target; a corpus seed lands instead, and it needs an explicit `!`-un-ignore line or it is silently untracked.
