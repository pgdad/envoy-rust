# Phase 48 — `48-accesslog-rf-no-route` — SPEC

**Pick (ADR-0105):** differentially WITNESS the **FIRST non-`-` `%RESPONSE_FLAGS%` value — `NR` (NoRoute)** — BYTE-EXACT on the no-route 404 path, and SET `response_flags = "NR"` at envoy-rust's H1 no-route `synth_404` arms (the value is hard-coded `"-"` at every record-build site today, `hcm.rs:1225`). The direct `%RESPONSE_FLAGS%` analogue of phase 45 (the FIRST failure-path `%RESPONSE_CODE_DETAILS%` value): phases 41–47 witnessed one access-log operator each (`%ROUTE_NAME%`, `%RESPONSE_CODE_DETAILS%`, `%UPSTREAM_CLUSTER%`, `%UPSTREAM_HOST%`) — `%RESPONSE_FLAGS%` has only ever been witnessed as the no-flags sentinel `"-"`; this phase witnesses its first real flag. **Foreshadowed by phase 47's own SPEC §4** ("`%RESPONSE_FLAGS%` (`NR`) — a separate operator … the natural next").

## §1 — Why this pick

`%RESPONSE_FLAGS%` already renders in all three encoders (`default_format.rs:60`, `json_format.rs:242`, `command_operator.rs:526`) and is differentially witnessed BYTE-EXACT for the no-flags case `"-"` (fixtures `0012`, `0040`, `0046`). The BEHAVIOR_CONTRACT row (`:1020`) explicitly flags the gap: _"06.2 always emits the literal `"-"` … Future fixtures exercising non-`-` flag combinations need per-flag equivalence rules added to this table."_ The `AccessLogRecord.response_flags: String` field is hard-coded `"-"` at the single H1 production record-build site (`hcm.rs:1225`); the H2 production site is `hcm.rs` (envoy-http2) `:948`; the remaining `response_flags: "-"` occurrences (`record.rs`, `hcm.rs:1844`) are `Default`/test-helper constructors, not production builder sites. (The encoder layer already renders a non-`-` flag in a unit test — `default_format.rs:303` uses `"UH"` — so NO encoder change is needed.)

`NR` (NoRoute — "No route configured for a given request, in addition to a 404 response code") is the cleanest first flag:
- **Deterministic + brace-free + config-driven** — a single static constant, exactly like phase 45's `no_healthy_upstream` / phase 46's `route_not_found`.
- **Reuses the already-proven trigger** — the no-route 404 path that phases 46 (route-miss) and 47 (host-miss) built fixtures `0054`/`0055` for. No new trigger surface.
- **State-1 recon-CONFIRMED at `envoyproxy/envoy:v1.33.0`** (this session — live container, see §3 PLAN-VERIFY 4): a route-miss probe AND a host-miss probe BOTH emit `{rc:404, rcd:"route_not_found", rf:"NR"}`; the happy `direct_response` 200 emits `rf:"-"`. Single clean flag, no combination.

This is the cheapest available pick that lights up a new operator value, recon-confirmed, with zero new trigger plumbing.
