**Goal:** Make file-based EDS endpoint assignments hot-reloadable — a running cluster whose endpoint set is EDS-supplied (`eds_cluster_config.eds_config.path_config_source.path`) picks up an atomic-rename edit WITHOUT a restart, atomically swapping the live endpoint set onto the round-robin LB, with the per-cluster `cluster.<name>.{update_attempt,update_success}` counters advancing past their initial-load values and `/config_dump?include_eds`'s `EndpointsConfigDump` reflecting the new assignment — bilaterally verified against upstream Envoy by fixture `0035-xds-eds-hot-reload` (Linux-CI-authoritative per ADR-0049 / ADR-0066).

**Architecture:** `Cluster.endpoints` is already a per-request-stateless input to the round-robin LB `pick()` (`crates/envoy-cluster/src/cluster.rs:80,274`), so hot-reload = an atomic pointer swap of the address `Vec`. Migrate that owned `Vec<SocketAddr>` to a shared swappable handle (`RwLock<Arc<Vec<SocketAddr>>>` — the phase-26 `route_config` handle pattern verbatim), GENERALIZE the phase-26 `RdsWatcher` into a domain-free `XdsFileWatcher` in `envoy-cluster` (which both `envoy-http1` [RDS] and `envoy-cluster` [EDS] consume), and add an EDS reload pipeline that re-reads the file on an mtime change, re-parses via the existing `eds.rs`, selects the CLA by `cluster_name`, re-validates endpoint addresses, and atomically stores the new `Arc`. Reload is **warm-reject for the IO/parse/wrong-name/bad-IP/empty-envelope classes** (last-good kept + the matching failure counter), but **mirrors Envoy's apply-empty for a present-but-empty CLA** (`update_success` + 0 hosts → 503 — ADR-0068, because `pick()` already handles empty gracefully). The watcher is spawned ONLY for PLAIN (no-HC/no-OD) EDS clusters (§0 finding 3 / ADR-0068); no cluster/listener/pool mutation — only the endpoint address set mutates.

**Tech Stack:** Rust (stable, pinned). `serde`/`serde_yaml` (existing `eds.rs` parser). `std::fs` (mtime poll + file read). `std::sync::RwLock` + `Arc` (the swap handle — dep-free). `tokio` + `tokio_util::sync::CancellationToken` (the watcher task — already in `envoy-cluster`). `envoy-stats` (counters — phase-21 registration reused + `update_rejected` added). **No new crate, no new top-level Cargo dep** (poll-based watch; dep-free swap handle; `envoy-cluster` already has tokio/tokio-util).

## §6.2 VERIFIED (state-2 PLAN-write, 2026-06-18 — ADR-0068) — the locked facts the tasks consume

The SPEC §6.2 6-item checklist, RESOLVED (full transcript: PROGRESS state-2 §6.2 entry; decision record: ADR-0068):

- **V1 (reload happens + readiness) — MATCHES.** Atomic-rename `[backend_1]→[backend_2]` re-targets live traffic with NO restart; settle **~7–8 ms** (flips within the first 50 ms poll); **zero 503 gap** (400-request hammer across a live swap = 0 non-200s); cluster stays up (no membership drop / no pool teardown). → Task-6 harness wait bound = poll on a 50 ms grid, ~2 s ceiling (the phase-26 wait-for-convergence, not a fixed sleep).
- **V2 (observability — D6) — second-backend body-marker swap CONFIRMED over liveness-flip.** Two single-endpoint backends distinguishable by a body marker; the swap re-targets observably. The liveness-flip (live→unreachable, 200↔503) is observable but noisier (request-time connect-refused, does not exercise membership/update, does not prove the new endpoint serves). **D6 uses the second-distinguishable-backend body-marker swap**; the 503 is reserved as the EXPECTED empty-assignment result.
- **V3 (`cluster.<name>.update_*` values) — MATCHES.** `update_attempt`/`update_success` = `1/1`(boot)→`2/2`(one reload)→`3/3`(two); the failure/rejected/empty trio = 0 on success. Fixture 0035 asserts `2/2` after one reload. **`membership_*` stays Envoy-only** (envoy-rust emits no `membership_total`, `cluster.rs:963`; `membership_healthy` is HC-gated) — assert ONLY `update_*`.
- **V4 (bad-reload taxonomy — locks §5.5 + D3) — envoy-rust MIRRORS Envoy in all five classes (ADR-0068 §Decision-2):**
  - (a) file unreadable / IO / malformed YAML / parse error → `update_attempt`+`update_failure`, KEEP last-good.
  - (b) envelope non-empty but no CLA matches the target `cluster_name` → `update_attempt`+`update_rejected`, KEEP last-good.
  - (c) a matched CLA has an unparseable/non-numeric endpoint address → `update_attempt`+`update_rejected`, KEEP last-good.
  - (d) **a matched CLA has `endpoints: []`** → `update_attempt`+`update_success`, **APPLY the empty set** (0 hosts → `pick()` None → `synth_no_healthy_upstream` 503); last-good NOT kept. **This MIRRORS Envoy** (the SPEC's warm-reject-empty projection is CORRECTED — ADR-0068; safe because `pick()` already returns None on empty, no panic, and the 503 path exists).
  - (e) truly-empty envelope `resources: []` (zero CLAs) → `update_attempt`+`update_empty`, KEEP last-good (no-op). Envoy DISTINGUISHES (e) from (d); envoy-rust mirrors the distinction.
- **V5 (`/config_dump` on reload) — MATCHES wire shape; the SPEC `last_updated` projection is WRONG.** EDS appears only under `?include_eds`, under `static_endpoint_configs[]` (the phase-21 ADR-0054 shape); the embedded assignment reflects the NEW endpoints after reload. **NO `last_updated`, NO `version_info`** on the EndpointsConfigDump entry (already the phase-21 shape — `endpoint.rs` `Endpoints { static_endpoint_configs }`). → **D5 shrinks to read-through-handle only** (no timestamp/version plumbing).
- **V6 (in-flight isolation + cursor-bounds) — MATCHES.** A request begun pre-reload completes against the OLD endpoint; only subsequent picks see the swap (§5.4 read-once). Cursor-bounds on a SHRINKING set is the envoy-rust-side `i % total` over the read-once snapshot (empty short-circuited) — D8 backstop-asserted.

## PLAN-time design decisions (the SPEC §3 PLAN-write calls, now resolved)

- **D1 handle type — `RwLock<Arc<Vec<SocketAddr>>>`** (the phase-26 `HCMConfig.route_config: RwLock<Arc<RouteConfiguration>>` pattern VERBATIM — `crates/envoy-http1/src/hcm.rs:139`). On `Cluster`: `current_endpoints(&self) -> Arc<Vec<SocketAddr>>` (read-once: `self.endpoints.read().unwrap().clone()` — a cheap Arc pointer clone) + `store_endpoints(&self, eps: Arc<Vec<SocketAddr>>)` (write: a single `*guard = eps`); both `pub(crate)`. **A `pub fn current_endpoints(&self) -> Arc<Vec<SocketAddr>>` is ALSO exposed on `ClusterHandle`** (delegating to the inner `Cluster`) — `envoy-admin`'s config_dump (Task 5) reads the live set through it (the `inner: Arc<Cluster>` is `pub(crate)`, NOT reachable cross-crate, so the public accessor is required — see Task 2). NO new `arc-swap` dep (§5.1). The per-request LB read snapshots the Arc ONCE at `pick()` entry (M26-1 read-once — see §carry-forwards). **Hot-path cost (SPEC §5.1 flagged):** the migration adds a `RwLock` read-acquire + an `Arc` refcount bump to the plain-cluster LB fast path (today a lock-free `AtomicUsize::fetch_add` + slice index — `cluster.rs:281-284`) on EVERY request. ACCEPTED: the read-lock is uncontended in steady state (writes happen only on the ~1 s-poll reload), and the phase-26 RDS precedent accepted the same `RwLock<Arc<…>>` read on its per-request route-table read. The `arc-swap` dep is the documented fallback IF state-5 profiling shows the LB hot loop regresses materially — not adopted now (dep-free default per §5.1).
- **D2 watcher placement — GENERALIZE to a domain-free `XdsFileWatcher` in `envoy-cluster`.** The phase-26 `RdsWatcher`'s only domain coupling is `crate::hcm::HCMConfig`; its poll/mtime/`CancellationToken`/`interval`/`JoinHandle` core is domain-free. `envoy-cluster` already has `tokio` + `tokio-util` (the outlier sweeper uses them) and is the LOWER shared crate (`envoy-http1` → depends on → `envoy-cluster`), so the generic core lives there; each domain provides a reload closure. **This folds the M19-1/M20/M21/M26 watcher-generalization debt (the "second instance reveals the abstraction" rule — SPEC §6.11). FALLBACK** (recorded, not default): if relocating `RdsWatcher` to consume the generic core threatens the fixture-0034 green baseline, ship a sibling EDS-only watcher reusing the pattern and record the RDS convergence as remaining debt — but the DEFAULT is the shared `XdsFileWatcher` with BOTH RDS and EDS as consumers.
- **D3 empty-assignment — MIRROR Envoy (apply-empty → 503), NOT warm-reject** (ADR-0068 V4(d)). The reload-vs-startup asymmetry is deliberate: `from_bootstrap` STILL rejects an empty cluster at STARTUP (`cluster.rs:804`, all-fatal); the RELOAD path applies-empty to mirror Envoy.
- **D4 — register `update_rejected` for `eds` clusters** (the phase-21 registration omits it — `cluster.rs:974-977`; it was Envoy-only because the all-fatal initial load never rejects). The reload reject paths (V4 b/c) tick it.
- **EDS+HC/OD cluster — NO watcher** (the SPEC §0-finding-3 reserved call — ADR-0068 §Decision-5): such a cluster's endpoints stay frozen at initial load (non-breaking, phase-21 behavior); the watcher is spawned ONLY for plain (no-HC/no-OD) EDS clusters, which GUARANTEES the D1 swap never desyncs an index-aligned `endpoint_health`/`outlier_detection` array (those are `None` on a plain cluster). A recorded deferred non-goal (§4).
