## Named focus-item verdicts (all PASS)

1. **The L6 chain-base / route-replace effective-policy model — PASS (adversarially verified).** `CsrfFilter::build_from_config` (`crates/envoy-filter/src/csrf.rs:85-107`) compiles the chain `CsrfPolicy` into `base_policy` and seeds `active_policy: base.clone()`; `apply_route_config` (`csrf.rs:110-118`) REPLACES `active_policy` with the route's `PerFilterConfig::Csrf` override **if present, else `.unwrap_or_else(|| self.base_policy.clone())`** — so a route with NO override is STILL guarded by the chain base (the key divergence from cors's `active_policy = None` inert pattern, ADR-0061 L6). The §6.2 2×2 matrix reproduces exactly: chain=100/no-override→enforce (403), chain=0/no-override→passthrough (200), chain=100/route=0→passthrough, chain=0/route=100→enforce — pinned by the four dedicated tests (`csrf.rs:324-375`). **Per-request leak-safety verified end-to-end:** both HCMs clone the pipeline fresh per request from the `Arc<FilterPipeline>` base (`envoy-http1/src/hcm.rs:616`, `envoy-http2/src/hcm.rs:458`) and call `apply_route_config` (h1:625 / h2:468) BEFORE `decode_headers` (h1:637 / h2:474), so `active_policy` is reset from the freshly-cloned `base_policy` every request — a prior request's route override cannot leak into the next. `apply_route_config(None)` (no matched route) also falls back to base, not to inert.
2. **The L3 `host_and_port` origin computation — PASS (one Minor, M24-2).** `host_and_port` (`csrf.rs:188-193`) reduces a value to the scheme-stripped `host[:port]` authority: if the value contains `"://"`, the authority after `"://"`; else the value verbatim. Traced panic-safe against adversarial inputs (`[::1]:8080`, `://x`, `http://:80`, multibyte, `http://`, `""`, pathless): the `split`/`split_once` operate on byte boundaries and `.next()` always yields ≥1 element, so no panic is reachable. IPv6 literals survive (`http://[::1]:8080` → `[::1]:8080` — there is no naive `:`-split). The four transcript probes reproduce exactly (`http://additional.example.com` → host-only, no `:80` synthesized; `localhost:10000/page?q=1` → trim at `/`; bare `localhost:10000` verbatim; `http://` → `""` → folded to missing-source). Source = `host_and_port(Origin)`, fallback `host_and_port(Referer)`, Origin precedence; the `.filter(|s| !s.is_empty())` (`csrf.rs:139`) correctly folds the empty-authority case into missing-source. **The one divergence (M24-2, non-gating):** the function trims at `['/', '?', '#']` whereas Envoy's `Url::hostAndPort()` locates the path via `/` only — a latent over-trim for a *pathless* URL carrying a query/fragment (`http://host?x` → `host` here vs `host?x` in Envoy). Practically unreachable: a browser-emitted `Origin` is `scheme://host:port` with no path/query, and a `Referer`'s path always begins with `/` (so the `/` arm fires first and the `?`/`#` arms are dead). Untested and unsanctioned by the oracle, hence recorded — but it cannot be triggered by a real request, so it is non-gating.
3. **The L5 stat mutual-exclusivity — PASS.** `decode_headers` (`csrf.rs:128-161`) is a strict early-return ladder: disabled-gate (129, no stat) → safe-method (132, no stat) → missing-source (140-143, `missing_source_origin` ONLY) → valid (154-156, `request_valid` ONLY) → invalid (157-160, `request_invalid` ONLY). No two `.inc()` sites are reachable for one request; the missing-vs-invalid boundary (no-source ticks `missing_source_origin` and NOT `request_invalid`) is pinned in isolation by `missing_source_ticks_missing_not_invalid` (`csrf.rs:311-320`) — a swap of the two non-valid `.inc()` sites would be caught. Matches the §6.2 controlled-sequence result (`request_valid:2, request_invalid:1, missing_source_origin:0→…→1`).
4. **The `validate_csrf_config` 0%-AND-100% acceptance — PASS (one Minor, M24-1).** The validator (`crates/envoy-config/src/bootstrap.rs:3179-3191`) does NOT use the `selects_deterministic()` shortcut (which is 100%-only: `numerator == denominator.value()`) — it uses the explicit both-endpoints check `if p.numerator != 0 && p.numerator != p.denominator.value()`, so a deterministic-0% (`numerator: 0`) config is correctly ACCEPTED while a fractional one is rejected (`UnsupportedNonDeterministicCsrfFilterEnabled`); a present `runtime_key` is rejected (`UnsupportedRuntimeKeyedCsrfFilterEnabled`). `denominator.value()` resolves HUNDRED/TEN_THOUSAND/MILLION correctly, so the 100% test is denominator-agnostic. Gated at BOTH the chain arm (`bootstrap.rs:2905-2912`) and the route override (`:2742-2746`) with the identical message type. RDS re-validation covered (the route walk lives in `validate_hcm`, re-invoked post-merge by `load_dynamic_resources`). **M24-1 (non-gating):** the validator test-net has no explicit `numerator: 0` → `is_ok()` assertion through `validate_csrf_config`, the exact case a `selects_deterministic()` regression would silently break.
5. **The L7 absent-filter route-walk ordering — PASS.** The generic `PerRouteConfigForAbsentFilter` `keys()` check (`bootstrap.rs:2730-2736`) fires BEFORE the csrf-override `values()` validation (`:2742-2746`), with an explicit breadcrumb comment — so a `csrf` per-route override on a route whose HCM chain lacks a `csrf` filter hits the absent-filter fatal-reject (ADR-0058 L7, reused verbatim), not a csrf-specific error. Pinned by `rejects_csrf_per_route_policy_for_absent_filter` (asserts `filter == "envoy.filters.http.csrf"`).
6. **The fixture-0032 content-length differential workaround legitimacy — PASS.** The two 200-POST probes send an explicit client `content-length: 0` because upstream Envoy auto-synthesizes it on a bodyless POST forwarded upstream while envoy-rust forwards only a client-supplied one — an H1-upstream-forwarding difference fully ORTHOGONAL to CSRF (confirmed: `grep` of `csrf.rs` returns zero content-length references; the allow/deny decision reads only method + Origin/Referer + Host). The fix touches only the SYMMETRIC request side (added to both proxies) and relaxes NO assertion: the `[200,403,200,200,403]` status sequence, the byte-exact 403 bodies (`expectations.yaml:69,95`), AND the byte-exact 200 echo-body cross-proxy equivalence (`:99`) all remain enforced. It masks no CSRF behavior — a silently-disabled filter still breaks the status sequence on the first compare (probes 2/5 would proxy to the echo-server and return 200).

### Minor (Nice to Have)

- **M24-1 (cluster A) — no explicit `numerator: 0` accept test through `validate_csrf_config`.** The `csrf_validator_tests` suite covers 100%-accept, 50%-reject, and runtime-key-reject at both chain and route levels, but there is no test asserting a deterministic-0% (`numerator: 0`) config is ACCEPTED — the exact case a `selects_deterministic()` regression would silently break. The code is correct (`bootstrap.rs:3189` uses the explicit both-endpoints check); the regression net has a gap. Add a `bootstrap_with_csrf_chain(0, None)` → `is_ok()` test. No behavioral impact.
- **M24-2 (cluster B) — `host_and_port` over-trims at `?`/`#`; Envoy's `Url::hostAndPort()` trims at `/` only.** `csrf.rs:190` splits on `['/', '?', '#']`, so a pathless URL carrying a query/fragment (`http://host?x`) yields `host` here vs `host?x` in Envoy. The doc-comment (`csrf.rs:185`) self-describes the broader behavior, so it is an intentional choice — but one the ADR-0061 L3 oracle ("the authority up to the next `/`") does not sanction, and it is untested (no `http://host?x` case; only `localhost:10000/page?q=1`, which has a leading `/` so the `?`/`#` arms are dead). Practically unreachable — a browser-emitted `Origin` carries no path/query and a `Referer` path always starts with `/`. **The most valuable M-track follow-up** given this project's byte-exact discipline: narrow the split to `value.split('/').next()` to match Envoy's `hostAndPort` exactly (it costs nothing — no real input reaches the `?`/`#` arms), or add a one-line breadcrumb + a pinning test documenting the intentional over-trim. No reachable behavioral impact.
- **M24-3 (cluster B) — duplicate `Origin`/`Referer` header disposition is untested (first-wins).** `header_ci` (`csrf.rs:136-137`) returns the FIRST match via `.find(...)`; the precedence-on-duplicate behavior is unverified against Envoy. RFC forbids multiple `Origin` headers and the codec layer would typically fold/reject them before filters run, so first-wins is almost certainly fine — this is upstream-codec territory. Consider a one-line note that duplicate-header disposition is delegated to the codec, or leave as-is. No behavioral impact.
- **M24-4 (cluster C) — `README.md:54` documentation imprecision.** The fixture README says the source is compared to "each `additional_origins` `StringMatcher` **(also scheme-stripped)**". The matcher value is NOT scheme-stripped by the filter — only the SOURCE origin is reduced via `host_and_port()`, then compared LITERALLY against the matcher's verbatim config string (confirmed `crates/envoy-config/src/matcher.rs` + §6.2 item 3, where `exact: "http://additional.example.com:80"` → 403 precisely because the matcher value is taken literally). The fixture is correct (it uses a bare `exact: "additional.csrf.test"`), so the test passes for the right reason; only the prose could mislead a future reader into thinking `exact: "http://additional.csrf.test"` would work. Reword to "(matched verbatim against the scheme-stripped source — the matcher value itself is NOT stripped; configure it as a bare `host[:port]`)". No behavioral impact.

**Confirmed-correct observations (NOT findings).** (a) The hand-rolled `Route` Deserialize/Serialize (`bootstrap.rs:1413-1531`) needed NO csrf change — it codecs `typed_per_filter_config` as a generic `BTreeMap<String, PerFilterConfig>`, so the new `Csrf` variant is handled automatically and byte-identical round-trip for pre-24 configs is preserved. (b) `req.method == *m` (`csrf.rs:132`) is case-SENSITIVE and correct — HTTP methods are case-sensitive RFC 7231 tokens; a lowercase `post` is a non-standard token Envoy's HTTP layer rejects (the transcript `FOOBAR → 400` precedent) before CSRF sees it. (c) The `host`-only target lookup (`csrf.rs:145-147`) is complete on BOTH protocols — H2's `:authority` is synthesized into a single `host` header (`envoy-http2/src/request.rs`) before filters run. (d) `unwrap_or("")` for a missing Host is safe — an empty target can never equal the non-empty `.filter`-guarded source. (e) The build-time `active_policy: base.clone()` (`csrf.rs:102`) is a harmless initial state, overwritten by `apply_route_config` on every request before decode. (f) The local `header_ci` duplication (`csrf.rs:195-202`) is the sanctioned SC5 N=3 decision (shared-util extraction is the standing-deferred M-track item). (g) The per-side fixture YAML asymmetry (admin/bind/`generate_request_id`/`request_headers_to_remove`/`{{BACKEND_HOST}}`) is the 0031/0008 precedent and provably comparison-neutral — the CSRF config is byte-identical across both sides, so no asymmetry can mask an allow/deny difference; the `request_headers_to_remove` even STRENGTHENS the echo-body compare by equalizing the forwarded upstream request. (h) Reusing `selects_deterministic()` inside `CompiledCsrfPolicy::From` (`csrf.rs:49-56`) is correct AT RUNTIME because the validator guarantees `numerator ∈ {0, denominator}` at config-load, so the runtime lowering is a pure boolean — the 100%-only semantics of `selects_deterministic()` are exactly right once 0%-vs-100% has already been validated.
