## §2. Strengths

1. **The deterministic-percentage scope cut is doctrinally clean and keeps the phase entirely inside the differential contract.** The validator (`crates/envoy-config/src/bootstrap.rs`) enforces the load-bearing check order — `http_status ∈ 100..=599` → `numerator > denominator.value()` (`FaultPercentageOutOfRange`) → `numerator ∉ {0, denominator.value()}` (`UnsupportedFractionalFaultPercentage`) — so a `200/100` operator typo reports the out-of-range error (not the fractional error), and a `50/100` fractional is rejected before it can reach a runtime that has no PRNG. `FractionalPercent::selects_deterministic` is a pure `self.numerator == self.denominator.value()` boolean computed once at `build_from_config` into `abort_selects`. The fractional rejection IS the mechanism that keeps the abort/pass outcome cross-proxy comparable (SPEC §5.6); no random draw exists to diverge between two independent proxies. Cluster A verified the order on-disk + that `validate_rejects_percentage_out_of_range` (200/100) and `validate_rejects_fractional_percentage` (50/100) lock both arms.

2. **The `FaultFilter` decode path is minimal-scope and obviously-correct.** `header_gate_matches` is `gate.iter().all(|m| m.matches(&req.headers))` — empty gate ⇒ `Iterator::all` over an empty slice returns `true` ⇒ the fault applies to all requests (AND semantics matching upstream Envoy). The abort counter increments EXACTLY ONCE per aborted request, inside the `StopAndSend` branch only, never on pass-through; the test `aborts_injected_counter_increments_once_per_abort_only` asserts value==2 after 2 aborts + notes "never on pass." `FAULT_ABORT_BODY` is byte-exact `b"fault filter abort"` (18 bytes, hex `66 61 75 6c 74 20 66 69 6c 74 65 72 20 61 62 6f 72 74`), `§6.2`-verified against `envoyproxy/envoy:v1.33.0` at PLAN-write — **no off-by-one this time** (unlike phase-10's RBAC 1-byte correction). The abort `FilterResponse` correctly uses `reason: None` (`reason: Option<&'static str>`).
