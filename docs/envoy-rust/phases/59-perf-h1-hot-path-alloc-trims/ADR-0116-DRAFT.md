## ADR-0116: Phase-59 pick + scope — **trim four per-request costs on the H1 downstream hot path (global Date mutex → per-worker thread-local; two access-log-only allocations elided; per-response wire buffer reused) with ZERO emitted-byte change — a regression-equivalence phase, NO new fixture**

- Date: 2026-07-05
- Status: accepted
- Context: A CPU flamegraph of `envoy-bin` under load (~14k rps on a k3s node) attributed ~84% of self-time to kernel network I/O and ~11.5% to envoy-rust app code — the proxy is I/O-bound, not compute-bound. Within that 11.5%, four per-request costs on the H1 downstream path are cheap to remove AND byte-neutral (independently verifiable, no parity risk): (1) `date.rs:14`'s global `Mutex<Option<(u64,String)>>` cache — the IMF-fixdate is already per-second-cached, but every response locks one shared mutex + clones the string, so aggregate `now_imf_fixdate()` throughput *falls* as worker threads rise (a micro-bench shows 1t 36.8 → 8t 10.3 Mops/s); (2) `hcm.rs:1030`'s unconditional `endpoint.to_string()` of the upstream `SocketAddr`, read only under the `!config.access_log.is_empty()` guard; (3) `hcm.rs:1293`'s unconditional clone of the whole response-header vec, whose sole consumer only borrows it; (4) `response.rs:31`'s fresh `Vec<u8>` per response (the sibling read buffer is already reused). None is a differential-parity gap — all four produce identical bytes — so this does not fit the "cheapest-strong differential leaf" mold; it is a regression-equivalence maintenance phase, taken because the wins are safe and measurable, explicitly NOT a claim that compute is the bottleneck (it is not).
- Options considered:
  - **Do nothing** — the app is only 11.5% of self-time; defer all micro-opts. Rejected: the Date mutex is a genuine cross-worker contention point (throughput regresses under load), and (2)/(3)/(4) are free allocations removable without parity risk.
  - **Date: add `arc-swap` / `httpdate`** — a lock-free crate or an off-the-shelf date crate. Rejected: adds a runtime dependency, and `httpdate` specifically re-opens the parent-04 §3 D1 hand-rolled lock. A `thread_local!` cache needs no dep and no format change.
  - **Date: `parking_lot::Mutex`** (already a dep) — faster uncontended, but still serializes workers. Rejected in favor of thread-local, which removes contention entirely.
  - **(2)/(3): keep the allocation, just gate it** vs **borrow instead of clone.** Chose gate-on-logging for (2) (the value is genuinely only needed when logging) and borrow-instead-of-clone for (3) (the owner `outgoing` is still alive at the consumer, so the clone is pure waste even when logging).
  - **(4): thread a reusable buffer** vs **vectored write (`writev`).** Chose buffer reuse here (contained, byte-identical, `write_to` kept as a wrapper); `writev` (eliminating the body memcpy) is a separate, larger follow-up, deliberately NOT bundled.
  - **Bundle the larger trims** (`filter_pipeline.clone()` per request `hcm.rs:722`, `req.headers.clone()` per attempt `hcm.rs:447`). Rejected: bigger blast radius, more tests in play — noted as a future `perf` carry-forward.
- Decision: Land §A–§E of the phase-59 SPEC: (§A) `date.rs` global `Mutex` → per-worker `thread_local! RefCell<Option<(u64,String)>>`, `now_imf_fixdate() -> String` and per-second semantics unchanged, `format_imf_fixdate` untouched (no `httpdate` dep); (§B) `hcm.rs:1030` gate `endpoint.to_string()` on `!config.access_log.is_empty()`; (§C) `hcm.rs:1293` delete the response-header clone, borrow `&outgoing.headers` at the one consumer (`:1396`); (§D) add `Http1Response::write_to_buf(resp, w, &mut Vec<u8>)` and reuse one per-connection buffer in `serve_connection` (`write_to` kept as a thin wrapper); (§E) a self-contained `#[ignore]`d `--release` micro-bench (`tests/perf_bench.rs`) + a `response.rs` byte-equivalence unit test proving `write_to_buf` == `write_to` including across buffer reuse. No new fixture, `Op`, `AccessLogRecord` field, runtime crate, dependency, `ConfigError` variant, or fuzz target (dev-only `bytes`).
- Rationale: All four trims are byte-neutral, so the acceptance is regression-equivalence (all `0001`-`0065` byte-identical) plus a same-or-better micro-bench, NOT a new differential witness. Thread-local removes the only genuine scalability defect (the Date mutex) with zero deps and zero format change, preserving the parent-04 D1 lock. The (2)/(3) elisions exploit the pre-existing `!access_log.is_empty()` guard, so they are unobservable to the differential suite (no fixture drives a no-logging request that inspects those operators). The buffer reuse mirrors the read-buffer pattern already in `serve_connection`.
- Consequences: `crates/envoy-http1/` only (`date.rs`, `hcm.rs`, `response.rs`, `Cargo.toml` dev-dep, new `tests/perf_bench.rs`); no H2/codec/`envoy-config` change → h2spec + `parse_bootstrap` fuzz unaffected. Local evidence this session: all workspace lib/bin tests green (envoy-http1 152, zero failures anywhere); fmt/clippy clean; the §E byte-equivalence test green; micro-bench Date 4.9×–14× at 2–8 threads + same-or-faster single-thread, response write 1.30×. The Docker-gated differential suite (`0001`-`0065`) and h2spec are expected green **by construction** (no emitted byte changes) and must be confirmed by CI (state-4 §7.5 gate). `#![forbid(unsafe_code)]` holds. OPENS an optional non-blocking `perf` carry-forward (the `filter_pipeline.clone()` + `req.headers.clone()` larger trims + the `writev` body-memcpy elimination); CONSUMES none.
