# Phase 52 — `52-accesslog-rf-connect-failure` — SPEC

**Pick (ADR-0109):** differentially WITNESS the **FIFTH non-`-` `%RESPONSE_FLAGS%` value — `UF` (UpstreamConnectionFailure)** — BYTE-EXACT on the upstream-connect-refused **503** path (a STATIC cluster whose single endpoint is the literal unreachable `127.0.0.1:1`, NO `circuit_breakers`, NO `retry_policy` → envoy-rust DIALS the endpoint, the kernel refuses the connect, and the connect-failure synth is returned downstream), by (i) **correcting envoy-rust's connect-failure synth status from `502` → `503`** at the three connect-failure arms (`crates/envoy-http1/src/hcm.rs:501`/`:530`/`:547`, each `AcquireOutcome::ConnectFailure(synth_status(502, close))`) so the response status matches Envoy, (ii) setting a NEW per-request boolean `connect_failure_for_log = true` when the FINAL attempt's outcome is `AttemptOutcome::ConnectFailure`, and (iii) extending the phase-48/49/50/51 `%RESPONSE_FLAGS%` derive at `crates/envoy-http1/src/hcm.rs:1305` to render `"UF"` when that boolean is set (today the derive renders `"URX"` from the phase-51 retry-limit-exceeded boolean, then maps the rcd strings `route_not_found => "NR"`, `no_healthy_upstream => "UH"`, `upstream_reset_before_response_started{overflow} => "UO"`, else `"-"`). The `%RESPONSE_FLAGS%` continuation after `NR` (phase 48) + `UH` (phase 49) + `UO` (phase 50) + `URX` (phase 51) onto the FIFTH already-implemented failure path. The sixteenth Observability access-log row. **This phase was explicitly DEFERRED by the phase-51 SPEC §4** ("the connect-failure `UF` flag — `UF`'s rcd carries an OS-derived brace phrase (non-deterministic) AND envoy-rust's connect-fail arm synthesizes 502 while Envoy returns 503/UF (a status divergence); … deferred (M45-2)"); the state-0 recon below resolves both points.

> **State-0 recon — the make-or-break design finding (this session, folded):** live `envoyproxy/envoy:v1.33.0` (digest `sha256:56da5afd…`, host Docker with `-p` port-mapping per memory `state0-recon-docker-needs-port-mapping`), a STATIC cluster with a single `127.0.0.1:1` endpoint (NO circuit_breakers, NO retry_policy) behind an H1 listener whose HCM carries a `{rc,rcd,rf}` `json_format` file access-log, driven by `GET /test`, emits — **byte-stable across 8 repeats AND across a container restart** — `{"rc":503,"rcd":"upstream_reset_before_response_started{remote_connection_failure|delayed_connect_error:_Connection_refused}","rf":"UF"}`, status `503`, with a 167-byte `text/plain` response body `upstream connect error or disconnect/reset before headers. reset reason: remote connection failure, transport failure reason: delayed connect error: Connection refused`. **Three consequences:** (a) the `%RESPONSE_FLAGS%` value is a single, clean, brace-free, deterministic constant **`UF`** (no combination) — witnessable byte-exact; (b) BOTH the `%RESPONSE_CODE_DETAILS%` (`…{remote_connection_failure|delayed_connect_error:_Connection_refused}`) AND the response BODY carry the OS-derived transport-failure reason (the `Connection refused` strerror / errno-class string — the M45-2 non-determinism class), so this phase must **NOT** witness the rcd or the body — the fixture logs ONLY `{rc, rf}` and the byte-exact-access-log driver does not compare the response body (§3.4); (c) envoy-rust TODAY returns **502** on this exact path (`AcquireOutcome::ConnectFailure(synth_status(502, close))`), a STATUS divergence from Envoy's 503 that was **never differentially validated** (no fixture drives a connect-failure status) — yet envoy-rust ALREADY returns 503 on the sibling overflow path (`synth_overflow`, ADR-0042/0043) which shares Envoy's `upstream connect error or disconnect/reset before headers` body family, so the connect-failure 502 is an internal inconsistency this phase corrects.

## §1 — Why this pick

`%RESPONSE_FLAGS%` already renders in all three encoders (`default_format.rs:60`, `json_format.rs:242`, `command_operator.rs:526`); phase 48 (ADR-0105) made the field per-request via the derive at `hcm.rs:1305`, phase 49 (ADR-0106) added `UH`, phase 50 (ADR-0107) added `UO`, phase 51 (ADR-0108) added `URX` (the first flag derived from a boolean discriminator, not from rcd). `UF` is the natural FIFTH flag and the FIRST that is ALSO a genuine differential-correctness fix:

- **The connect-failure path is already implemented; the recon shows a real status divergence.** envoy-rust's H1 proxy arm classifies a kernel-refused connect into `AcquireOutcome::ConnectFailure` and synthesizes a **502** (`hcm.rs:501` pool arm — the differential-relevant path — plus the two non-pool arms `:530`/`:547`); this flows through the retry loop as `AttemptOutcome::ConnectFailure` and is returned downstream verbatim. Upstream Envoy v1.33.0 returns **503** with `%RESPONSE_FLAGS% = UF` on the identical trigger (state-0 recon). The 502 is an UNVALIDATED guess — no differential fixture exercises connect-failure status — so this phase validates that surface against Envoy for the first time and corrects it to 503. envoy-rust ALREADY uses 503 for the sibling `synth_overflow` path (ADR-0042/0043 corrected an H2 overflow 502→503 for exactly this reason), so 503 for connect-failure is the consistent, contract-correct disposition.
- **State-0 recon-CONFIRMED at `envoyproxy/envoy:v1.33.0`** (this session — live container, digest `sha256:56da5afd…`, host Docker `-p` port-mapping): the connect-refused topology (a STATIC cluster, single `127.0.0.1:1` endpoint, no circuit_breakers, no retry_policy) with a `{rc,rcd,rf}` `json_format` access-log, driven by `GET /test`, emits byte-stable across 8 repeats AND a container restart:
  ```
  status 503;  rf = "UF"  (rcd + body carry the non-deterministic transport-failure reason — NOT witnessed)
  ```
  `%RESPONSE_FLAGS%` = **`UF`** is a single, clean, brace-free, deterministic constant. So `UF` is byte-exact cross-proxy and witnessable; the rcd and the body are the M45-2 non-deterministic class and are excluded from the fixture (logged: `{rc, rf}` only; body not compared by the driver — §3.4).
- **1:1 with the connect-failure final outcome, via a clean boolean discriminator (the phase-51 pattern).** Because the connect-failure rcd is the non-deterministic `…{remote_connection_failure|delayed_connect_error:…}` (NOT a unique deterministic string), the `%RESPONSE_FLAGS%` derive **cannot key on rcd** for `UF` (exactly as phase-51's `URX` could not key on the shared `via_upstream`). `UF` requires a **separate boolean discriminator** — `connect_failure_for_log` — set when the final attempt's `AttemptOutcome` is `ConnectFailure` (the same classification that drives the connect-failure synth). This is the second flag NOT 1:1 with a unique rcd, reusing phase-51's boolean-discriminator mechanism verbatim.

envoy-rust on this path TODAY emits status `502` (WRONG — Envoy returns 503) + `rf:"-"` (WRONG — the derive maps only the URX boolean + the three rcd strings; the connect-failure rcd falls to `_ => "-"`), so this phase corrects a real STATUS divergence AND lights up the fifth flag, recon-confirmed, on a fully-built connect-failure trigger.

- **The downstream-termination `DC` flag** — requires a timing-dependent mid-request downstream disconnect (hard to drive deterministically in a fixture); remains deferred (the `DC` slice of **M45-2**).
- **Retry-exhausted-connect-failure** (a `retry_policy` whose `num_retries` are all connect-failures) — Envoy may render a combined `UF`+`URX` or `UF` alone there; un-recon'd combination, out of fixture scope (`0060` uses NO `retry_policy` → a single clean `UF`). Deferred (the §A ordering keeps `URX` first so this combination, if it ever sets both, renders deterministically — the PLAN confirms, §3.1).
- **H2 connect-failure `%RESPONSE_FLAGS%`** — the H2 record-build site (`envoy-http2/src/hcm.rs`) hard-codes `"-"`, and there is no H2 access-log differential driver; deferred (**M45-1**).
- **Witnessing the connect-failure `%RESPONSE_CODE_DETAILS%` and the response body** — both carry the OS-derived transport-failure reason (non-deterministic across environments — M45-2); NOT witnessed (the fixture logs `{rc, rf}` only; the driver does not compare the body).
- **`%RESPONSE_FLAGS%` flag-combination rendering** (multiple simultaneous flags) — out of scope; the no-retry connect-failure path emits a single clean `UF` (recon-confirmed).
