## §1 — Why this pick

The candidate menu (`STATE.md`, left by the phase-56 close-out) weighed: **M56-1**'s remaining H2 `%RESPONSE_FLAGS%` values (`UH`/`UO`/`URX`/`UF`/`UC`), now unblocked by phase 56's `Driver::Http2AccessLogByteExact` harness; the `DC` flag (rejected six consecutive times, ADR-0102 through ADR-0113, still timing-dependent); M53-2's BEHAVIOR_CONTRACT "(H1)" qualifier (a trivial doc-only fix, not worth a whole phase on its own); and heavier family pivots (gRPC ALS/OTLP/tracing, CDS/LDS hot-reload, non-deterministic LB policies). `UH` is the cheapest-strong-differential leaf this session:

- **It is the DIRECT sequel to phase 56's driver-opening work**, exactly mirroring the H1 cadence phases 49→50→51→52→53 established after phase 48 built the H1 `NR` pattern. `UH` is H1's OWN second flag (phase 49, ADR-0106) — reusing the identical trigger config (fixture `0057`'s `metadata_match` NO_FALLBACK subset-miss) with only the listener's `codec_type` changed, so the config-authoring risk is minimal.
- **State-0 recon found the gap is a clean two-site fix, not a re-architecture.** Unlike H1 (where `UH`'s rcd was ALREADY correct at phase 49, needing only the flags-derive arm), H2's gap also includes a genuine status-code correctness bug (502 vs Envoy's 503) — but this is EXACTLY the same shape of fix phases 51 (`UF`) and 53 (`UC`) already performed on the H1 side, so there is a direct precedent to mirror, not a novel design.
- **It closes a standing loose end.** The `BEHAVIOR_CONTRACT.md:1031` note "the H2 no-healthy arm returns 502" has sat un-investigated since phase 56's SPEC drafting; this phase investigates and fixes it in the same motion as the `UH` witness, since both trace to the identical code site.
- **The `DC` flag remains genuinely harder** (timing-dependent, six consecutive rejections) — nothing this session changes that assessment.
