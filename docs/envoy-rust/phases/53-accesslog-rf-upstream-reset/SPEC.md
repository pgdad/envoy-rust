## §1 — Why this pick

`%RESPONSE_FLAGS%` already renders in all three encoders (`default_format.rs:60`, `json_format.rs:242`, `command_operator.rs:526`); phase 48 (ADR-0105) made the field per-request via the derive at `hcm.rs:1343`, then 49 added `UH`, 50 added `UO`, 51 added `URX` (the first boolean-discriminator flag), 52 added `UF` (the second boolean-discriminator flag, + the connect-failure 502→503 correction). `UC` is the natural SIXTH flag and the SECOND that is ALSO a genuine differential-correctness fix:

- **The reset path is already implemented; the recon shows a real status divergence.** envoy-rust's H1 proxy arm classifies a post-connect send/recv failure (the upstream closed/reset before delivering a complete response) into `AttemptOutcome::Reset` and synthesizes a **502** (`hcm.rs:618`); this is returned downstream verbatim. Upstream Envoy v1.33.0 returns **503** with `%RESPONSE_FLAGS% = UC` on the identical trigger (state-0 recon). The 502 is an UNVALIDATED guess — no differential fixture exercises upstream-disconnect status — so this phase validates that surface against Envoy for the first time and corrects it to 503, exactly as phase 52 corrected the sibling connect-failure 502→503. envoy-rust ALREADY uses 503 for the `synth_overflow` (ADR-0042/0043) AND the connect-failure (ADR-0109) paths, so 503 for the reset path is the consistent, contract-correct disposition.
- **State-0 recon-CONFIRMED at `envoyproxy/envoy:v1.33.0`** (this session — live container, digest `sha256:56da5afd…`, host Docker `-p` port-mapping, a Docker bridge network with an `alpine/socat … EXEC:/bin/true` accept-then-close backend): the upstream-disconnect topology with a `{rc,rcd,rf}` `json_format` access-log, driven by `GET /`, emits byte-stable across 8 repeats AND a container restart:
  ```
  status 503;  rf = "UC";  rcd = "upstream_reset_before_response_started{connection_termination}"  (deterministic — but logged {rc,rf}-only this phase)
  ```
  `%RESPONSE_FLAGS%` = **`UC`** is a single, clean, brace-free, deterministic constant. So `UC` is byte-exact cross-proxy and witnessable.
- **1:1 with the reset final outcome, via a clean boolean discriminator (the phase-51/52 pattern).** The reset path's rcd is the SHARED `via_upstream` (the same `outcome:None` discriminator family as the connect-failure path), so the `%RESPONSE_FLAGS%` derive **cannot key on rcd** for `UC` (exactly as `URX`/`UF` could not). `UC` requires a **separate boolean discriminator** — `reset_for_log` — set when the final attempt's `AttemptOutcome` is `Reset`. This REUSES the loop-scoped `final_outcome` capture phase 52 already added (`hcm.rs:1082`/`:1184`), so the envoy-rust change is even smaller than phase 52: one `matches!` line + one derive branch + the one-arm 502→503 + the §G sweep. This is the third flag NOT 1:1 with a unique rcd.

envoy-rust on this path TODAY emits status `502` (WRONG — Envoy returns 503) + `rf:"-"` (WRONG — the derive maps only the URX/UF booleans + the three rcd strings; the reset rcd `via_upstream` falls to `_ => "-"`), so this phase corrects a real STATUS divergence AND lights up the sixth flag, recon-confirmed, on a fully-built reset trigger.
